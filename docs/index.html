Face Screen Lock

Automatically locks your screen when you step away — powered by real-time facial recognition, fully local with no cloud dependency, no accounts, no subscriptions.

Supports Windows, macOS, and Linux. Bilingual UI (English / فارسی). All face data stays on your machine.

Features

Core 7 features

All smart capabilities built into the monitoring engine.

DETECT Face Detection & Recognition Real-time owner identification via webcam ⌄
How it works

Captures a frame every check_interval_seconds (default 2s). Haar Cascade detects faces in the frame; each detected face is compared against the trained LBPH model. Confidence below confidence_threshold is considered a match.

Related config
check_interval_seconds int · 2 confidence_threshold int · 70 min_face_size int · 100 away_seconds_threshold int · 15
Note

Lower confidence_threshold = stricter (fewer false positives). Raise it if the app doesn't recognize you; lower it if it accepts strangers.

LEARN Adaptive Learning Auto-updates model as appearance changes over time ⌄
How it works

When a recognition exceeds adaptive_learning_confidence_threshold, the frame is saved as a new sample. After adaptive_learning_interval_minutes passes, the model retrains silently. Oldest adaptive samples are pruned when adaptive_learning_max_samples is exceeded. Original enrollment files (owner_*.png) are never deleted.

Related config
adaptive_learning bool · true adaptive_learning_interval_minutes int · 10 adaptive_learning_confidence_thresholdint · 40 adaptive_learning_max_samples int · 80
Adaptive samples location
data/faces/adaptive_{unix_timestamp}.png
SECURE Activity Awareness Skips lock while you're actively typing or moving the mouse ⌄
Platform implementation
macOS ioreg Windows GetLastInputInfo Linux xprintidle / X11
Security ceiling

Activity override only holds for activity_override_max_seconds (default 120s). After that, if the owner's face hasn't been confirmed, the normal lock timer resumes — preventing bypass by prolonged typing.

Related config
require_activity_check bool · true activity_grace_seconds int · 5 activity_override_max_seconds int · 120
SECURE Stranger Detection Locks faster when an unrecognized face is visible ⌄
Behavior

If a face is detected but confidence doesn't match the owner, the app switches to a shorter timeout (unrecognized_face_seconds_threshold) and ignores any keyboard/mouse activity override. The tray icon turns dark red during this state.

Related config
lock_faster_on_unrecognized_face bool · true unrecognized_face_seconds_threshold int · 5
Tray icon
⬤ Dark Red — fast-lock active
DETECT Meeting Mode Multiplies lock timeout when a meeting app is running ⌄
Detected apps (default)
Zoom Microsoft Teams Skype Webex GoToMeeting
Limitation

Detection is process-name based — Zoom open but idle still activates meeting mode. Browser-based meetings (Google Meet in Chrome) cannot be detected.

Related config
meeting_mode_enabled bool · true meeting_mode_multiplier int · 3 meeting_app_names list · []
I18N Bilingual UI Full English and Persian (فارسی) support with RTL layout ⌄
Scope
System tray menu Settings window activity.log entries
Switch language

From the tray menu → Language → English / فارسی. Change is applied live — no restart needed. Persisted in config.json key language.

Related config

Quick Start

Setup 3 steps

From zero to a running face-lock in three steps.

STEP 1 Install Dependencies pip install — no build tools, no compilation required ⌄
WIN Windows
pip install -r requirements.txt
LIN Linux
pip install -r requirements.txt

# If tkinter is missing:
sudo apt install python3-tk
MAC macOS
# Do NOT use Apple's system Python — Tcl/Tk 8.5 crashes the settings window.
# Use Homebrew instead:
brew install python@3.12 python-tk@3.12
pip install -r requirements.txt
STEP 2 Enroll Your Face One-time guided wizard — captures ~40 samples, trains LBPH model ⌄
WIN Windows
python enroll.py
MAC / LIN macOS / Linux
./enroll.sh
Wizard steps
1 · Forward 2 · Left turn 3 · Right turn 4 · Slightly up 5 · Slightly down 6 · Low-light optional
Output
data/model.yml trained LBPH model data/faces/owner_*.png ~40 samples
Re-enroll when
Drastic appearance change Recognition consistently failing
STEP 3 Start Monitoring System tray icon (recommended) or headless mode ⌄
WIN Windows
python menubar.py           # system tray icon (recommended)
python monitor.py           # headless — no icon
python monitor.py --debug   # live camera preview for tuning
MAC / LIN macOS / Linux
./run.sh               # system tray icon (recommended)
./monitor.sh           # headless — no icon
./monitor.sh --debug   # live camera preview for tuning
macOS — required system setting
System Settings → Lock Screen
→ "Require password after screen saver begins or display is turned off"
→ set to: Immediately

# Without this, pmset only turns the display off — nothing actually locks.

Security model
Owner face confirmed          →  never locks
No face + recent activity     →  delays lock (up to activity_override_max_seconds)
No face + no activity         →  locks after away_seconds_threshold
Stranger face visible         →  locks after unrecognized_face_seconds_threshold
                                 (activity override is ignored)
ADAPTIVE Adaptive Learning Settings Auto-update model from high-confidence detections ⌄
adaptive_learning bool · true adaptive_learning_interval_minutes int · 10 adaptive_learning_confidence_threshold int · 40 adaptive_learning_max_samples int · 80
Note

adaptive_learning_confidence_threshold should be lower than confidence_threshold — adaptive samples directly influence the model, so only high-certainty frames are accepted.

MEETING Meeting Mode Settings Extend lock timeout when a meeting app is running ⌄
meeting_mode_enabled bool · true meeting_mode_multiplier int · 3 meeting_app_names list · []
Example — add custom app
"meeting_app_names": ["FaceTime", "Discord"]

# Effective timeout during meeting:
# away_seconds_threshold × meeting_mode_multiplier
# e.g.  15 × 3 = 45 seconds

Auto-Start at Login

Boot 3 platforms

Run Face Screen Lock automatically every time you log in.

WIN Windows — Startup Folder Simplest method — no admin rights required ⌄
Method 1 — Startup shortcut
# Open the Startup folder:
Win+R → shell:startup

# Create a shortcut with:
Target:   python "C:\path\face-screen-lock\menubar.py"
Start in: C:\path\face-screen-lock
Method 2 — Task Scheduler
Task Scheduler → Create Task
  General   → name: FaceLock
              "Run only when user is logged on"
  Triggers  → At log on
  Actions   → Program: python
              Arguments: menubar.py
              Start in:  C:\path\face-screen-lock
MAC macOS — LaunchAgent Native launchd integration — survives reboots and re-logins ⌄
Plist location
~/Library/LaunchAgents/com.nima.facelock.plist
Plist content
<?xml version="1.0" encoding="UTF-8"?>
<plist version="1.0"><dict>
  <key>Label</key>
  <string>com.nima.facelock</string>
  <key>ProgramArguments</key>
  <array><string>/full/path/to/run.sh</string></array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
</dict></plist>
Load / unload
launchctl load   ~/Library/LaunchAgents/com.nima.facelock.plist
launchctl unload ~/Library/LaunchAgents/com.nima.facelock.plist
LIN Linux — systemd User Service Managed by systemd — auto-restart on failure ⌄
Service file location
~/.config/systemd/user/facelock.service
Service file content
[Unit]
Description=Face Lock Monitor

[Service]
ExecStart=/full/path/to/run.sh
Restart=on-failure
Environment=DISPLAY=:0

[Install]
WantedBy=default.target
Enable & start
systemctl --user daemon-reload
systemctl --user enable --now facelock.service

Limitations

Warning 4 known issues

Known constraints to be aware of before relying on this tool.

ALGO LBPH — Not Deep Learning Lightweight but less accurate than dlib/face_recognition ⌄

LBPH is fast and requires no GPU, but degrades significantly in low light or at extreme angles. It is suitable for personal/office use — not a replacement for Windows Hello, Touch ID, or enterprise security.

Very low light → false negatives Extreme angles → miss detection Identical twins not distinguished
CAM Shared Webcam Conflict Zoom/Teams using the same camera blocks frame capture ⌄

Most OSes allow only one app to exclusively read a webcam. If Zoom/Teams is using it, frame capture fails silently.

Behavior
Safe — does NOT lock
Trade-off
Not monitored while camera is busy
MEET Browser-Based Meetings Google Meet / browser tabs cannot be detected ⌄

Meeting detection is process-name based. A Chrome tab running Google Meet appears as just chrome to the OS — indistinguishable from a regular browser window. Only standalone executables (Zoom, Teams…) work.

MAC macOS Display Sleep ≠ Lock pmset only turns off the display — requires a system setting ⌄

pmset displaysleepnow is the most reliable cross-version command on macOS (CGSession and keyboard shortcuts behave inconsistently across versions). It only turns the display off — the system settings below are required for it to lock.

Required setting
System Settings → Lock Screen
→ "Require password after screen saver begins or display is turned off"
→ set to: Immediately
